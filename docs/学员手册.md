## 一、语言基础

**文件**：`Lesson01Basics.java`　|　**课时**：90 分钟　|　**难度**：★☆☆　|　**前置**：无

### 1. 学习目标

1. 能说出 8 种基本类型的大小，能解释「金额为什么不用 `double`」。
2. 能预测一段传参代码的输出，并能讲清「Java 只有值传递」。
3. 能区分 `==` 与 `equals`，能说出 `Integer` 缓存的边界值。
4. 能独立写出带重载、带返回值的方法并正确调用。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | 变量与字面量、运算符、`if`/`for`/`while`/`switch`、数组、方法、`String` 常用 API | 不看文档写出「求数组最大值」 |
| 懂原理 | 整数除法截断、`i++`/`++i`、值传递、`String` 不可变、常量池、`Integer` 缓存 | 能预测输出 |
| 能工程化 | 命名规范、循环拼接用 `StringBuilder`、常量提取 | 代码能直接过 review |

**课内章节顺序**：基本类型 → 运算符 → 流程控制 → 数组 → 方法 → `String` → 包装类 → 练习

**易错提醒**

- 整数除法会截断：`1 / 2 == 0`，要 `1.0 / 2`。
- 两个内容相同的字符串 `==` 可能是 `false`（一个在常量池、一个 `new` 出来）→ 内容比较一律 `.equals()`。
- `Integer` 只缓存 `-128 ~ 127`：`Integer a = 128, b = 128; a == b` 是 `false`
  （两个 `int` 写成 `128 == 128` 当然是 `true` —— 区别在于装箱后比的是引用）。
- `null` 的包装类参与算术会抛 `NullPointerException`。
- 方法里把形参**重新赋值**（`arr = new int[]{...}`）对外面没影响；改元素才有影响。

### 3. 运行命令

```bash
./scripts/run.sh com.hczn.learn.Lesson01Basics
```

### 4. 练习

| 层次 | 任务 |
| --- | --- |
| 基础（必做） | 求数组最大值、平均值；判断字符串是否回文 |
| 进阶 | 不用 `Map`，统计字符串里每个字符出现次数（提示：`char` 可以直接当下标） |
| 挑战 | 写一个 `swap(int a, int b)`，解释为什么它对外面没效果，并给出两种「真能交换」的写法 |

### 5. 自测（遮住右列口头回答）

| 自测问题 | 参考答案要点 |
| --- | --- |
| Java 是值传递还是引用传递？ | 只有值传递；对象传的是「引用的拷贝」，所以能改内容、换不掉对象 |
| `==` 和 `equals` 什么时候用哪个？ | `==` 比基本类型值或对象地址；内容比较一律 `equals` |
| `Integer a = 128, b = 128; a == b` 为什么是 false？ | `Integer` 只缓存 `-128~127`，装箱超范围会 `new` 新对象，比的就是引用 |
| `int a = 1; a = a++;` 之后 `a` 是几？ | 1（先把旧值赋回去，再自增） |

## 二、面向对象

**文件**：`Lesson02Oop.java`　|　**课时**：90 分钟　|　**难度**：★★☆　|　**前置**：第 1 课

### 1. 学习目标

1. 能设计一个有封装、有构造器的类。
2. 能用「父类引用指向子类对象」写出多态代码，并能解释运行时怎么选到子类方法。
3. 能说清**抽象类与接口**的选择依据。
4. 能正确重写 `equals`/`hashCode`，并解释两者的契约。
5. 能说清**成员内部类与静态嵌套类**的区别。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | 类/对象/构造器、`private`+getter/setter、`extends`、`implements`、枚举 | 能写出「形状 + 求面积」的类层次 |
| 懂原理 | 多态（动态绑定）、`static` 属于类而非对象、`final` 三种含义、equals/hashCode 契约 | 能解释「为什么父类引用能调子类方法」 |
| 能工程化 | 优先组合而非继承、用接口替代 `if-else`、枚举替代魔法值 | 能把一段 `switch` 重构为多态 |

**课内章节顺序**：类与对象 → 封装 → 继承与多态 → 抽象类与接口 → 内部类 → equals/hashCode → 枚举

**易错提醒**

- **字段没有多态**：只认声明类型。多态只发生在方法上。
- 自己写了带参构造器，编译器就不会再补无参构造器。
- `equals` 相等 → `hashCode` 必须相等，否则放进 `HashSet`/`HashMap` 会「找不到」。
- **成员内部类**必须 `new Outer().new Inner()`（它隐式持有外部实例）；
  **静态嵌套类**可以直接 `new`。
  对照看仓库里两个文件：`TestDemo.java`（成员内部类）vs `Algorithms.java`（静态嵌套类）。
- getter 返回集合字段时要返回副本，否则外部能绕过封装改内部数据。

```bash

grep -n "class ListNode" src/main/java/com/hczn/learn/Algorithms.java src/test/java/com/hczn/java/TestDemo.java
```

### 4. 练习

| 层次 | 任务 |
| --- | --- |
| 基础（必做） | `Shape` 接口 + 圆/矩形 + 求总面积，用多态而不是 `if-else` |
| 进阶 | 写一个不可变类（字段全 `final`、构造器赋值、不暴露可变引用），并用 JUnit 验证 |
| 挑战 | 把一段 5 分支的 `switch` 重构成多态，说明重构后新增一种类型要改几处 |

### 5. 自测

| 自测问题 | 参考答案要点 |
| --- | --- |
| 为什么必须同时重写 equals 和 hashCode？ | 哈希容器先用 hashCode 定位桶，再用 equals 比；只改一个会「放进去找不到」 |
| 抽象类和接口怎么选？ | 骨架/is-a 关系用抽象类；能力/需要多实现用接口 |
| `TestDemo` 里的 `ListNode` 为什么不能直接 `new`？ | 它是成员内部类，隐式持有外部实例引用 |
| 字段能被「覆盖」吗？ | 不能，字段是静态绑定，只有方法有多态 |

## 三、集合与泛型

**文件**：`Lesson03Collections.java`　|　**课时**：90 分钟　|　**难度**：★★☆　|　**前置**：第 2 课

### 1. 学习目标

1. 面对一个需求能立刻选对集合并说清理由。
2. 能说出 `HashMap` 的五步工作原理。
3. 能解释 `ConcurrentModificationException` 的成因，并写出三种正确的删除方式。
4. 能解释 `List<? extends T>` 与 `List<? super T>` 的读写边界（PECS）。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `ArrayList`/`LinkedList`、`HashSet`/`TreeSet`、`HashMap`/`TreeMap`/`LinkedHashMap` | 能根据需求选型 |
| 懂原理 | 动态数组 vs 双向链表、哈希桶、红黑树、可变 key 的坑、`modCount` | 能解释「为什么快/为什么抛异常」 |
| 能工程化 | 用接口类型声明变量、预估容量避免扩容、`removeIf` 替代手写循环 | 代码不出现「零件式」实现类声明 |

**课内章节顺序**：List → Set → Map → HashMap 原理 → 遍历中删除 → 排序 → 泛型 → 练习

**选型表（要背下来）**

| 需求 | 选它 | 理由 |
| --- | --- | --- |
| 按位置快速读写 | `ArrayList` | 数组，随机访问 O(1) |
| 频繁在头部增删 | `LinkedList` / `ArrayDeque` | 链表 O(1)；但按下标找是 O(n) |
| 去重、不关心顺序 | `HashSet` | 底层就是 `HashMap` 的 key |
| 去重 + 有序 | `TreeSet` | 红黑树，O(log n) |
| 按 key 快速查 | `HashMap` | 平均 O(1) |
| 按 key 排序 | `TreeMap` | O(log n) |
| 保留插入顺序 | `LinkedHashMap` | 哈希 + 双向链表 |
| 多线程 | `ConcurrentHashMap` / `CopyOnWriteArrayList` | 第 5 课 |

**`HashMap` 五步（要能背）**

```
① hash = key.hashCode() 做高位扰动
② index = hash & (capacity - 1)     // 位运算比 % 快，前提是容量为 2 的幂
③ 桶空 → 直接放；桶有元素 → 挂成链表
④ 链表 > 8 且容量 >= 64 → 转红黑树（O(n) → O(log n)）
⑤ size > capacity * 0.75 → 容量翻倍 + rehash
```

**易错提醒**

- `Arrays.asList` / `List.of` 返回**不可变视图**，`add` 会抛 `UnsupportedOperationException` → 包一层 `new ArrayList<>(...)`。
- `HashMap` 的 key 必须**不可变**：放进 map 后改掉参与 `hashCode` 的字段，就再也 `get` 不到了。
- 遍历中删除有三种正确写法：`iterator.remove()` / `removeIf(...)` / 倒序 `for` 删除。
- PECS 一句话：**只想读用 `extends`；只想写用 `super`**。
- `Comparator.comparing(X::getA).reversed().thenComparing(X::getB)` 里，B 是**升序**
  —— `reversed()` 只反转它前面那条链。

### 3. 运行命令

```bash
./scripts/run.sh com.hczn.learn.Lesson03Collections
```

### 4. 练习

| 层次 | 任务 |
| --- | --- |
| 基础（必做） | 统计一段文本的词频，按词频降序输出 |
| 进阶 | 用 `Comparator` 实现「按年龄降序，年龄相同按姓名升序」 |
| 挑战 | 写一个 `copy(List<? super T> dest, List<? extends T> src)`，解释两个通配符为什么方向相反 |

### 5. 自测

| 自测问题 | 参考答案要点 |
| --- | --- |
| 需要「按插入顺序遍历」的 Map 选哪个？ | `LinkedHashMap` |
| `HashMap` 为什么容量是 2 的幂？ | 为了用 `hash & (capacity-1)` 代替取模 |
| `List<? extends Number>` 能 `add` 吗？ | 不能，编译器不知道具体子类型 |
| 为什么倒序删除能避免异常？ | 删除只影响后面的元素，没走过的下标不受影响 |

## 四、异常与 IO / NIO

**文件**：`Lesson04ExceptionsIo.java`　|　**课时**：90 分钟　|　**难度**：★★☆　|　**前置**：第 3 课

### 1. 学习目标

1. 能画出异常体系树，并判断一个异常是否受检。
2. 能说出「何时该捕获、何时该向上抛」，能避免「捕获后什么都不做」。
3. 能设计自定义异常并用异常链保留根因。
4. 能用 `Files` 完成「读文件 → 处理 → 写文件」，并保证资源一定关闭。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `try`/`catch`/`finally`、`throws`、`Files.readAllLines`/`writeString`、`BufferedReader` | 能写一个安全读文件的方法 |
| 懂原理 | 受检 vs 非受检、`finally` 执行时机、异常链、try-with-resources 关闭顺序 | 能预测含 `return` 的 `finally` 代码结果 |
| 能工程化 | 自定义业务异常、异常带上文、临时文件在 `finally` 清理 | 能重构「一个方法里 5 个 catch」 |

**课内章节顺序**：异常体系 → try/catch/finally → 受检 vs 非受检 → 自定义异常与异常链 → try-with-resources → `Files` → 缓冲流 → `Files.walk` → 练习

**易错提醒**

- **`finally` 里的 `return` 会覆盖 `try` 的返回值**。
- `catch (Exception e) { }` 是在吞异常 —— 出事了没有任何线索。
- 自定义异常要**把 cause 传进去**：`new ServiceException("读取配置失败: " + path, ioException)`，
  堆栈里才能看到真正的原因。
- try-with-resources 的关闭顺序是**后进先出**（与打开顺序相反）。
- 读写文件一定要**显式指定 `UTF_8`**，否则中文乱码。
- `Stream<Path>`（`Files.walk` 的返回值）也要 `try-with-resources` 关闭。

**判断准则**：**能补救的**（文件不存在、网络超时）用受检异常往上抛；
**不能补救的程序 bug**（下标越界、空指针）让它尽快暴露。

## 五、多线程与并发

**文件**：`Lesson05Concurrency.java`　|　**课时**：90 分钟　|　**难度**：★★★　|　**前置**：第 4 课

### 1. 学习目标

1. 能解释 `start()` 与 `run()` 的区别。
2. 能制造并修复一个竞态条件，能说清「为什么加锁能修好」。
3. 能说出 `volatile` 能保证什么、不能保证什么。
4. 能说出线程池的核心参数含义，能识别一段代码有没有死锁风险。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `Thread`/`Runnable`、`synchronized`、`AtomicInteger`、`ExecutorService`、`ConcurrentHashMap` | 能写一个线程安全的计数器 |
| 懂原理 | 竞态三要素、可见性与原子性、CAS、锁粒度、死锁四条件 | 能解释「为什么结果不是 40000」 |
| 能工程化 | 优先不共享、用线程池而不是 `new Thread`、并发容器而不是手写同步 | 能把共享可变状态消除掉 |

**课内章节顺序**：start vs run → 竞态条件 → 修复（synchronized / 原子类）→ `volatile` → CAS → 线程池 → 并发集合 → 死锁

**修复优先级（要背）**：不共享 ＞ 不可变 ＞ 线程封闭 ＞ 加锁

**`count++` 为什么不是原子的（画得出来才算懂）**

```
T1: 读 count=100 ──────────────► 算 101 ─► 写 101
T2:       读 count=100 ─► 算 101 ──────────► 写 101   ← 覆盖了 T1 的结果
```

**三种 `synchronized` 用法**

| 写法 | 锁的是谁 |
| --- | --- |
| 修饰实例方法 | `this` |
| 修饰静态方法 | 该类的 `Class` 对象 |
| 修饰代码块 | 括号里指定的对象 |

**易错提醒**

- `volatile` 只保证**可见性**和禁止重排序，**不保证原子性**。`volatile int count; count++` 照样丢更新。
- `run()` 不会开新线程，它只是普通方法调用，在**当前线程**执行。
- `start()` 对同一个线程对象调两次会抛 `IllegalThreadStateException`。
- 单核也会有竞态（线程切换在任何核心数下都会发生）。
- `Executors.newFixedThreadPool` 用的是**无界队列**，任务堆积会 OOM；生产建议直接 `new ThreadPoolExecutor(...)`。
- `ThreadPoolExecutor` 的扩容顺序反直觉：**先塞队列，队列满了才扩到 max**。
- 忘记 `shutdown()` 会导致 JVM 不退出。
- 预防死锁最简单的办法：**所有线程按同一顺序获取锁**；演示用 `tryLock(timeout)`。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |

| 会用 | Lambda、方法引用、Stream 常用操作、`Collectors`、`Optional`、`LocalDate` | 能把一段 for 循环改成 Stream |

**Stream 结构（背下来）**

```
list.stream()             // 建流（数据源）
   .filter(条件)           // 中间操作：惰性，返回新流
   .map(转换)              // 中间操作
   .collect(toList())     // 终止操作：到这里才真正执行
```

**易错提醒**

- **惰性求值**：只有中间操作、没有终止操作 → 一行都不会执行。
- **流只能消费一次**，重复用会抛 `stream has already been operated upon or closed`。

- `Collectors.toMap` 遇到重复 key 会抛异常，要传合并函数 `(a, b) -> b`。
- `Optional` 只当**返回值**用，不要当参数、不要当字段。
  `if (opt.isPresent()) { opt.get(); }` 只是把判空换了个写法。
- `SimpleDateFormat` 不是线程安全的；新代码用 `DateTimeFormatter`。
- 函数式接口 = **只有一个抽象方法**的接口（可以用 `@FunctionalInterface` 标注）。

**内存结构（要能画）**

| 区域 | 线程 | 放什么 |

**Maven 生命周期（包含关系，不是并列）**

```

```

**JUnit 4 要点**

- 类名以 `Test` 结尾（或 `Test` 开头），方法必须 `public void`、无参数。
- 生命周期：`@BeforeClass`（static，一次）→ `@Before` → `@Test` → `@After` → `@AfterClass`。
- 断言把期望值写在前面：`assertEquals(期望, 实际)`。
- 数组/内容比较用 `assertArrayEquals`，别用 `assertEquals`（那比的是引用）。
- 异常用 `assertThrows`（4.13+），能顺带断言消息；`@Test(expected=...)` 是老写法。
- ⚠ JUnit 4 **没有** `assertDoesNotThrow` / `assertTimeout`，那是 JUnit 5 的。
- `BigDecimal` 不要用 `assertEquals` 比，要 `compareTo(...) == 0`。

**易错提醒**

- **`-cp` 必须指向包的「根目录」**，不是类文件所在目录。
  正确：`java -cp out/classes com.hczn.learn.Lesson07Jvm`；错误：`-cp out/classes/com/hczn/learn`。
- `javac` 报「找不到符号」通常是对依赖的类没一起编译、或没把 `target/classes` 加到 `-cp`。
- **对象里的基本类型字段在堆上**，不是「基本类型都在栈上」。
- 局部变量不用 GC 管（随栈帧消失）；对象才由 GC 管。
- `System.gc()` 只是**建议**，不是立即回收。
- `StackOverflowError` = 栈太深（递归没终止）；`OutOfMemoryError` = 堆/元空间不够。
- 静态字段和静态块按**代码书写顺序**执行，且只在类初始化时执行一次。
- 反射慢的原因：方法查找 + 访问检查 + 无法内联优化；它还会破坏封装。

## 八、算法与数据结构

**文件**：`Lesson08Algorithms.java` + `Algorithms.java` / `AlgorithmsTest.java`（35 个用例）
**课时**：90 分钟　|　**难度**：★★★　|　**前置**：第 1 课、第 3 课

### 1. 学习目标

1. 能对一段代码说出时间/空间复杂度。
2. 掌握 7 类模板：双指针、哈希、链表、栈队列、二叉树、排序二分、DP。
3. **能先写暴力解，再按套路优化**，而不是一上来就想最优解。
4. 能手写反转链表、二分查找、快排，并说清边界条件。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | 双指针、哈希映射、哑节点、快慢指针、栈/队列、BST、二分、DP 三步 | 每类能独立写出 1 题 |
| 懂原理 | O(n²) → O(n) 的优化路径、状态定义、`mid` 溢出写法 | 能解释优化为什么成立 |
| 能工程化 | 纯函数抽到 `Algorithms`（可测）、先想边界再写 | 每写一题先列边界用例 |

**课内章节顺序**：复杂度 → 数组双指针 → 哈希 → 链表 → 栈队列 → 二叉树 → 排序与二分 → 动态规划 → 刷题方法

**复杂度速查**

| 复杂度 | n = 10⁵ 时大致可行？ | 典型算法 |
| --- | --- | --- |
| O(1) | 随便 | 哈希查找 |
| O(log n) | 随便 | 二分 |
| O(n) | ✅ | 一次遍历、哈希 |
| O(n log n) | ✅ | 排序、分治 |
| O(n²) | ❌（10¹⁰ 次） | 双重循环 |
| O(2ⁿ) | ❌ | 暴力子集枚举 |

**优化的四条固定套路（要背）**

1. 去掉重复计算 → 哈希 / 前缀和 / DP
2. 利用有序 → 排序 + 双指针 / 二分
3. 用栈处理「最近的相关元素」→ 单调栈
4. 递归/分治处理树形结构

**链表反转三步（要背）**

```
next = cur.next      // ① 先存后继
cur.next = prev      // ② 反转指向
prev = cur; cur = next   // ③ 前进
```

**二分统一模板（要背）**

```java
int left = 0, right = n - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;   // 防溢出
    // ...
}
```

**DP 三步法**

1. **状态**：`dp[i]` 表示什么？
2. **转移**：`dp[i]` 从哪些更小的状态来？
3. **边界**：最小规模时是多少？

**易错提醒**

- `twoSum` 给的是**无序**数组 → 不能直接用双指针（要哈希）。
- 改 `cur.next` 之前**必须先保存 `next`**，否则链断掉。
- 链表题一律用**哑节点**，能省掉一半边界判断。
- `(left + right) / 2` 可能整型溢出 → 用 `left + (right - left) / 2`。
- 快排取最右为基准 + 已排序数据 = O(n²)，递归深度 O(n)，可能栈溢出。
- `isValidBst` 不能只比较父子节点，要传上下界（约束是整棵子树）。
- DP 数组长度常写成 `n` 而不是 `n+1` → 答案差 1。
- 单调栈**存下标**（要算距离），不是存值。
- 课程里的实测数字只看**数量级**，别当精确基准。

## 九、网络编程

**文件**：`Lesson09Network.java`　|　**课时**：90 分钟　|　**难度**：★★★　|　**前置**：第 4 课、第 5 课

### 1. 学习目标

1. 能说清 IP / 端口 / TCP / UDP / HTTP 的关系。
2. 能写出一个「能超时、能关闭、能中断」的服务端 + 客户端。
3. 能用 `HttpClient` 发同步与异步请求，能处理失败。
4. 能解释「为什么端口要写 0」「为什么要设 `setSoTimeout`」。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `ServerSocket`/`Socket`、`DatagramSocket`、`URI`、`HttpClient`、`URLEncoder` | 能写一个回显服务端 |
| 懂原理 | 阻塞调用模型、「一连接一线程」的瓶颈、超时与半关闭 | 能解释「为什么设了超时就不卡了」 |
| 能工程化 | 端口不写死、编码显式、资源必关、HTTP 客户端配超时与重试 | 代码能直接过 review |

**课内章节顺序**：概念 → URI → 本机地址 → TCP 回显 → UDP → HTTP 客户端

**端口分段**

| 范围 | 用途 |
| --- | --- |
| 0~1023 | 系统保留（80 HTTP、443 HTTPS、22 SSH） |
| 1024~49151 | 注册端口，一般应用用这段 |
| 49152~65535 | 动态/临时端口，客户端发起连接时系统随机分配 |

**两条流程（要背）**

```
服务端：bind → accept（阻塞）→ 拿到 Socket → 读写字节流 → close
客户端：connect → 拿到 Socket → 读写字节流 → close
```

**网络代码三件套**：**超时、可关闭、可中断**。缺一个就会「偶发卡死」。

**五条坑（要背）**

1. `accept`/`read` 都是阻塞的，必须放单独线程（或 NIO）。
2. 一定要设超时（`setSoTimeout` / connect timeout），否则网络抖动会挂死线程。
3. 每个 `Socket` 都要 `close`，用 try-with-resources。
4. 文本流要显式指定编码（`UTF_8`），否则中文乱码。
5. 「一连接一线程」扛不住高并发，生产用线程池或 NIO（Netty）。

**易错提醒**

- 端口写死 8080 会被占用 → 用 `new ServerSocket(0)` 让系统分配空闲端口。
- `#片段` 不会发给服务器，只在浏览器本地用。
- 拼 URL 时中文/空格必须 `URLEncoder.encode(...)`。
- 本地测试不要写死 `192.168.x.x`（换网络就失效），用 `getLoopbackAddress()`。
- HTTP：**连接超时和读超时是两个不同的设置**，都要设。
- `HttpClient` **不会自动重试**，生产代码要自己加重试 + 指数退避。
- UDP 不保证送达、不保证顺序、不保证只到一次。

## 十、JDBC 与数据库

**文件**：`Lesson10Jdbc.java` + `WalletService.java` / `WalletServiceTest.java`（10 个用例）
**课时**：90 分钟　|　**难度**：★★★　|　**前置**：第 4 课、第 7 课

### 1. 学习目标

1. 能背出 JDBC 五步曲，能独立写出一个增删改查。
2. **默认就不会写出 SQL 注入**（任何用户输入都走占位符）。
3. 能正确使用事务，能解释「为什么失败后余额一分没动」。
4. 能解释 H2 依赖为什么是 `runtime` scope。
5. 能解释「为什么要把转账逻辑抽到 `WalletService`」。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `DriverManager`、`PreparedStatement`、`ResultSet`、`executeUpdate`、`addBatch` | 能写完整 CRUD |
| 懂原理 | 占位符预编译、影响行数、事务与 `autoCommit`、check-then-act 竞态、连接池 | 能解释注入为什么被挡住 |
| 能工程化 | 逻辑抽到可测的 Service、事务边界清晰、连接由池管理 | 能写出可测的 DAO/Service |

**课内章节顺序**：JDBC 是什么 → DDL → INSERT → **SQL 注入** → SELECT → UPDATE/DELETE → 事务 → 批量 → 元数据

**五步曲（要背）**

```
1. 拿连接    DriverManager.getConnection(url, user, password)
2. 造语句    conn.prepareStatement(sql)
3. 设参数    statement.setInt(1, 100)        ← 从 1 开始！不是 0
4. 执行      executeQuery() 返回 ResultSet / executeUpdate() 返回影响行数
5. 关资源    try-with-resources
```

**事务模板（要背）**

```
conn.setAutoCommit(false);
try {
    ...多条 UPDATE...
    conn.commit();
} catch (SQLException e) {
    conn.rollback();
    throw e;
} finally {
    conn.setAutoCommit(true);      // 必须还原！
}
```

**易错提醒**

- **参数下标从 1 开始**，不是 0。
- SQL 注入演示：输入 `x' OR '1'='1` 拼进 SQL 就变成
  `... WHERE name = 'x' OR '1'='1'` → 引号被提前闭合，全表被查出来。
  占位符则只当普通字符串。
- **排序字段用不了占位符**，只能白名单校验（唯一例外）。
- `executeUpdate` 一定要检查**影响行数**，0 行 = 静默失败。
- 扣款要用 `UPDATE ... WHERE balance >= ?` 再看影响行数，
  **不能**先 `SELECT` 查余额再扣（并发下 check-then-act 会超卖）。
- `autoCommit` 必须在 `finally` 里还原，否则连接被别人复用时状态是脏的。
- `rs.getInt()` 遇到 SQL `NULL` 返回 0，分不清「值是 0」还是「值是 NULL」→ 用 `getObject`/`wasNull`。
- 批量插入要配合事务，否则每条还是各自提交。
- 生产不要每次 `DriverManager.getConnection`（那是建物理连接），要用连接池（HikariCP）。

## 十一、手写集合，看穿底层

**文件**：`Lesson11Collections.java` + `MiniArrayList.java` / `MiniHashMap.java` / `MiniCollectionsTest.java`（33 个用例）
**微基准**：`src/test/java/com/hczn/learn/benchmark/`（三个 JMH 基准类）
**课时**：90 分钟（JMH 建议课后跑）　|　**难度**：★★★　|　**前置**：第 3 课、第 8 课

### 1. 学习目标

1. 能解释 `ArrayList` 的容量与元素个数的区别，能说出扩容策略与代价。
2. 能解释 `HashMap` 的「数组 + 链表」结构，能画出 get 的查找路径。
3. 能说清「坏 hashCode 会把哈希表变成链表」。
4. 能正确使用 `hashCode` / `equals`，能解释「可变 key」为什么是灾难。
5. 能说出「为什么手写 `System.nanoTime` 计时不可信」，以及 JMH 解决了什么。

### 2. 知识点

| 层次 | 内容 | 掌握标准 |
| --- | --- | --- |
| 会用 | `MiniArrayList` 的增删改查与迭代器、`MiniHashMap` 的 put/get/remove | 能读懂并能改这两个类 |
| 懂原理 | 1.5 倍扩容、`modCount` 与 fail-fast、`hash & (cap-1)`、扰动函数、负载因子 0.75、rehash、冲突退化 | 能白板画结构图 |
| 能工程化 | 预估容量避免扩容、`equals`/`hashCode` 契约、用 JMH 而不是手写计时 | 能写一个可用的基准 |

**课内章节顺序**：为什么看底层 → ArrayList 扩容 → O(1) vs O(n) → **fail-fast** → MiniHashMap → 冲突 → 扩容 → hashCode 与可变 key → 与 JDK 对比 → JMH

**两个核心结论（要背）**

```
ArrayList = 动态数组
  随机访问 O(1) | 末尾追加均摊 O(1) | 中间增删 O(n) | 扩容 1.5 倍并复制

HashMap = 数组 + 链表（+ 红黑树）
  平均 O(1) | 最坏 O(n) | 容量 2 的幂 + 扰动函数 | 负载因子 0.75 | 扩容 2 倍
```

**定位公式（要背）**

```java
int hash  = h ^ (h >>> 16);           // 扰动：把高 16 位异或到低位，减少碰撞
int index = hash & (capacity - 1);    // 位运算代替取模，前提是容量为 2 的幂
```

**易错提醒**

- **容量 ≠ size**：`new ArrayList<>()` 容量是 10，`size()` 是 0。
- 删除元素时必须把数组槽位**置 `null`**，否则对象被数组一直引用，GC 回收不了（内存泄漏）。
- **哈希冲突只影响性能，绝不影响正确性**。
- **fail-fast 是「尽力检测」而不是「一定检测」**：
  删**第一个**元素会抛 `ConcurrentModificationException`，但删**倒数第二个**元素
  **根本不抛异常**（删完 `size` 变小，`hasNext()` 先返回 `false`，没走到检查）。
  → **没抛异常 ≠ 写对了。** 一律用 `iterator.remove()` / `removeIf`。
- 先比 `hash` 再比 `equals`：`int` 比较极快，能省掉大量昂贵的 `equals`。
- JDK 8 之后：桶内链表 > 8 且总容量 ≥ 64 → 转红黑树，O(n) → O(log n)（防恶意 hash 攻击）。
- `new HashMap<>(1000)` 的实际容量是 1024（向上取到 2 的幂）。
- 已知规模时用 `new HashMap<>(expectedSize / 0.75 + 1)` 避免反复扩容。
- **可变 key 是灾难**：放进去后改掉参与 hashCode 的字段，`get` 返回 `null`，
  但 `size()` 还是 1 —— 元素成了「永远取不出来的垃圾」。
- 扩容 rehash 时**先存 `next`** 再改 `node.next`，否则链表丢失。

**JMH 解决的四个坑**

| 坑 | 不解决会怎样 |
| --- | --- |
| JIT 预热 | 测到的是「解释执行」的速度，不是稳态 |
| 死代码消除 | JIT 发现结果没被使用，直接把整个计算删掉 |
| 常量折叠 | 编译器提前算完，测出来是 0 |
| JVM 间干扰 | 多个基准互相影响 |

## 卡住了怎么办

按顺序做，**不要直接看答案**：

1. **读报错。** 只看三行：异常类型、消息、**最下面的 `Caused by`**。
   栈顶那一行通常不是根因。
2. **定位到「谁抛的」。** 把栈里**你自己写的类**那一行找出来（`com.hczn.learn.` 开头的）。
3. **缩小范围。** 把 `main` 里其他部分注释掉，只留报错那几行。
4. **验假设。** 用 `System.out.println` 或者断言，打印「你以为的值」和「实际的值」。
   九成的 bug 是「我以为这里是 X，其实是 Y」。
5. **看对照写法。** 打开 `src/main/java/com/hczn/learn/` 里对应的课，
   对比自己写的和示例写的，**找不同点**。
6. **还是没有？** 把你的最小复现代码 + 完整报错记下来再问别人 —— 能提出好问题本身就是能力。

### 三个高频「明明没错」的报错

| 报错 | 真实原因 |
| --- | --- |
| `找不到或无法加载主类` | `-cp` 指错了，或类名没写全限定名 |
| `找不到符号` | 依赖类没一起编译，或没把 `target/classes` 加进 `-cp` |
| `UnsupportedOperationException` | 在 `Arrays.asList` / `List.of` 的结果上做了 `add`/`remove` |
